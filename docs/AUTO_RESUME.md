# Автоматическое продолжение

Настроен локальный наблюдатель для **этого же чата Codex Desktop**. Он использует установленный MCP-плагин `codex-app-tools`, а не создаёт новую CLI-сессию. Никаких платных сбросов, переключения аккаунта или модели.

## Условия работы

- Компьютер включён и не спит, Codex Desktop остаётся открытым, интернет доступен.
- Запуск выполняется из текущего чата: процесс наследует адрес локального канала приложения и идентификатор чата. Учётные данные не копируются в файлы.
- Наблюдатель проверяет состояние раз в минуту. Автоматическое продолжение возможно при `idle` или `systemError`, завершённом с подтверждённой ошибкой лимита ходе и `ordinaryUsageAllowed: true` от самого приложения. Статус `systemError` без ошибки лимита не даёт разрешения.
- После обнаружения ошибки выдерживается минимум 90 секунд и состояние повторно проверяется перед отправкой.
- Отправляется одна команда продолжения в тот же чат с прежними настройками модели. Запись о попытке сохраняется **до** отправки в отдельный журнал с `fsync`: при таймауте повторной отправки не будет. Повреждённый журнал блокирует действия. Временная блокировка файла состояния Windows обрабатывается ограниченными повторными записями; невозможность обновить информационный снимок не завершает процесс.
- Ручная остановка, успешное завершение, бюджет сессии, ошибки входа, соединения или неизвестное состояние не вызывают продолжение.
- Один наблюдатель на проект защищён блокировкой ОС. Лимит: 6 попыток на сохранённое состояние, время жизни запуска — 48 часов. После 5 подряд ошибок соединения он завершится со статусом `manual-attention`.
- После завершения проекта агент создаёт `.local/project-complete.json`; наблюдатель завершается автоматически. Перезапуск приложения или компьютера может потребовать повторного запуска наблюдателя.

## Команды PowerShell

Из каталога проекта:

```powershell
.\scripts\auto-resume.ps1 -Action Status
.\scripts\auto-resume.ps1 -Action Stop
# Только из терминала/инструмента целевого чата Codex Desktop:
.\scripts\auto-resume.ps1 -Action Start
```

`processVerified: true` подтверждает, что PID принадлежит процессу этого скрипта. `lastCheck` должен обновляться примерно раз в минуту. `active` означает, что агент работает и повторный запуск не требуется; `waiting-limit` — ожидается разрешение сервера; `resume-sent` — отправлена команда; `manual-attention` — нужна проверка журнала.

Состояние: `.local/auto-resume-state.json`; события: `.local/auto-resume.jsonl`; журнал однократных попыток: `.local/auto-resume-reservations.jsonl`; ошибки процесса: `.local/auto-resume.stderr.log`. Эти файлы исключены из Git. В них нет истории чата, учётных данных или полной информации аккаунта.

## Проверено

- Реальный MCP-клиент видит текущий чат как `active / inProgress`; CLI-демон показывал устаревшее `notLoaded / interrupted`, поэтому его использование отклонено.
- Серверный признак `ordinaryUsageAllowed` читается через нативный инструмент приложения.
- Тесты логики покрывают доступность лимита, активный ход, ручную остановку, дубли, бюджет, другой проект, неизвестный статус, задержку и предел попыток.
- Запуск скрытого процесса, проверка его PID, блокировка второго запуска и остановка проверяются локально.
- 17 ноября обнаружен и исправлен реальный сбой первого запуска: Desktop обозначил ошибку лимита как `systemError`, а первоначальный фильтр принимал только `idle`. Позже процесс завершился на Windows `EPERM` при переименовании снимка. Добавлены регрессионные проверки фактического формата ошибки и блокировки файла.
- После исправления проверен полный реальный цикл: 17 ноября в 08:22 UTC наблюдатель зафиксировал `waiting-limit`, дождался разрешения сервера и в 13:02 UTC (18:02 по Екатеринбургу) отправил ровно одну команду в этот же чат. Агент продолжил работу с сохранённых файлов. Запись попытки имеет результат `sent`. Это подтверждает работу текущей версии; изменение интерфейса плагина при обновлении Codex может потребовать адаптации клиента.

Источник протокола приложения — установленный `codex-app-tools/server.mjs` и его MCP-схемы. [Официальная справка команд Codex](https://learn.chatgpt.com/docs/developer-commands?surface=cli#cli-codex-queue) описывает отдельную CLI-очередь; она здесь не используется, поскольку приложение и демон оказались разными процессами.
